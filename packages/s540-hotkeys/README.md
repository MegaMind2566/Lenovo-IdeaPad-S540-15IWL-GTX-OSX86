# S540 Tasti

Functional integration of the missing Lenovo IdeaPad S540-15IWL GTX (81SW)
hotkeys: microphone mute (F4), Wi-Fi/Bluetooth power and restoration (F7),
camera-firmware event reporting (F8), and macOS screen lock request (F9 / Command+L).

On the tested S540, F8 does not block camera video. App 0.1.3 corrects the
earlier success popup: EC state 0 and a successful firmware readback are not
evidence of a disabled camera. The camera remains available after Photo Booth
is closed and reopened. F8 reports that the video block is unavailable. This
update corrects feedback; it does not implement a working camera block.

The kernel component matches VPC2004/VPC0 only and requires the observed
`_CFG=0xFE0D0014`. Deferred ACPI notifications expose a versioned immutable
snapshot and a bounded numeric event ring. It uses the VPC protocol already
implemented in Linux ideapad-laptop and YogaSMC, restricted to event reads and
the camera power command. It does not implement sensors, battery policy, fans,
Fn-mode or arbitrary ACPI operations. There is no user write interface.

The Cocoa companion performs microphone and radio actions through macOS APIs.
It never records audio or general keyboard events. The screen-lock binding consumes Command+L, the sequence generated by direct F9
on the confirmed keyboard, and requests Control+Command+Q. The user explicitly
accepted replacing the ordinary browser Command+L shortcut. Fn+F9 is no longer
handled. Other shortcuts are not consumed; key text is never stored.

Camera ownership is not inferred from capability flags. An observed change
since the valid baseline is accepted without writing; an unchanged state on a
fresh camera key event is toggled once and read back. Failure disables camera
writes until a fresh load or wake baseline. This is a guarded integration policy,
not a claim that the complete combination has already been tested on the laptop.

The installer preserves the existing EFI, bootloader chain, Windows and audio
driver. It tracks exactly the installed bundles and user LaunchAgent for restore.
Read `LEGGIMI.txt` for the single installation and functional check.

Host fixtures, native compilation, packaging, target loading and actual function
are distinct milestones. Native CI does not load the driver or change host radios.

On the target 81SW, driver 0.1.0 is loaded and publishes a ready snapshot with
zero query failures. The user confirmed F4 microphone mute, F7 Wi-Fi/Bluetooth,
F9 screen lock and their HUDs with app 0.1.2. The latest F8 event has mask
`0x0080`, CameraState 0 and result 7 (firmware changed), while video remains
available after reopening the camera app. The EC flag cannot be treated as a
camera privacy indication on this target.

## Camera feedback correction 0.1.3

F8 reports an unavailable video block, including when firmware reports a
successful state change. It never emits a confirmed camera-off HUD. No camera
recording, USB reset, assistant termination, permission changes or guessed
vendor commands are added. The signed kernel remains the original 0.1.0.
Owned app 0.1.0, 0.1.1 and 0.1.2 installations can be upgraded without a driver
reload. The update preserves the existing app preference and backup chain.

## App feedback 0.1.2

The app has a keyboard-and-shortcut icon and a matching template menu-bar icon.
Brief nonactivating HUD panels show the result of F4/F7/F8/F9 actions without
notification permissions, sound, or focus changes. Baseline reads, reconnects,
and periodic status polling do not produce action feedback. Camera feedback
reported firmware state. App 0.1.3 replaces that camera feedback with the
confirmed limitation above. Screen-lock feedback reports a request.

The microphone action uses the input mute exposed by CoreAudio. In the installed
VoodooHDA 3.6.10 implementation that control zeros the input mixer and restores
its saved input gain when unmuted; the app does not maintain a second gain store.
The guarded decoder from 0.1.1 and the original signed kernel 0.1.0 are retained.
Owned app versions 0.1.0 and 0.1.1 can be upgraded without a driver reload.

## App correction 0.1.1

Apple's IOKit unserializer represents OSNumber32 as signed CFNumber32. The
observed CFG 0xFE0D0014 therefore arrives as -32702444; the prior unsigned-only
app decoder rejected the complete Snapshot. The correction normalizes the bits
only for CFG and CameraState, retains strict sequence/time validation, and tests
actual signed CFNumber instances. Driver 0.1.0 is reused byte for byte. An owned
0.1.0 installation is upgraded by replacing the app and receipt, without loading,
unloading or recompiling the driver. Native validation is app-only.
