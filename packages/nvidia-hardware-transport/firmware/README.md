# Firmware and RPC preflight

This CPU-only component validates NVIDIA's pinned ELF64 GSP container layout and plain MCTP/NVDM/RPC v03_00 framing. It does not read a device, upload firmware, create DMA mappings or initialize GSP/RM. `PROVENANCE.json` pins eleven NVIDIA source inputs at `1a82fbfda8f321b056eb3568850f9316c5e465c5` (615.78.08). Reference excerpts are not compiled. The implementation is an explicit hardened parser, not an unchanged NVIDIA parser.

The parser checks little-endian ELF64 identifiers, complete section/program tables, bounded string names, exclusive bounds, checked arithmetic, power-of-two alignment, required-section uniqueness, range overlaps and the exact `.fwversion` string. TU117 selects the `tu11x` signature family, inside the `gsp_tu10x` container family. Required data are `.fwimage`, `.fwsignature_tu11x` and the GNU build-id note. The selected section views borrow immutable CPU memory and are cleared on every failure.

The parser uses stricter bounds than the upstream reference: upper limits are exclusive, `shstrndx` must be less than `shnum`, strings must terminate within the name table, and selected image/signature sections cannot overlap. Extended section numbering, containers larger than 128 MiB, more than 512 section/program headers, name tables above 64 KiB, and names above 255 bytes are outside this bounded profile. Successfully parsing a container does not authenticate its signature.

The SHA256 implementation hashes actual bytes and is checked against standard vectors. **No real firmware image or approved firmware hash is included.** The readiness gate rejects even a correctly formatted synthetic image as `UnapprovedImage`. The build manifest deliberately records empty firmware-asset and approved-hash lists. Loading stays blocked until an actual matching release image is obtained, its provenance/size/hash is reviewed, and the hardware transport is ready. `realImageReady` therefore remains false independently of successful parser checks.

RPC checks cover the 24-byte unencrypted MCTP/NVDM prefix, the exact 32-byte NVIDIA RPC header, release-pinned magic/version/vendor/type, mutually consistent lengths, stale markers and exact expected sequences. The bounded local policy accepts one plain single-packet envelope; encrypted/confidential-compute and continuation records are outside this profile. The CPU request window rejects overlapping work, detects timeout without waiting, preserves a pending request on malformed replies and clears ownership on completion, cancellation or timeout. This is local envelope/preflight logic, not a live message queue.

The layout planner checks page-aligned allocation ranges and rejects overflow, insufficient capacity and page-table capacity above one 4 KiB page of 64-bit addresses. It produces sizes and offsets only. No addresses, page table or buffers are published to a GPU.

`selfCheck()` runs fixed synthetic positive and malformed fixtures under the same code used by native checks. It separately reports parser, RPC, layout and cleanup results. The native harness adds standard SHA256 vectors and truncated/malformed buffers. Native checks and kernel startup fixture checks do not establish real firmware validity, GPU responses, queue contention, interrupt handling or GSP startup.
