# Manual retained first-initialization control

This separate IOResources frontend exposes a privileged snapshot, a once-per-boot initialization request, and a genuine stop request. Loading the module performs no PCI lookup or original GPU initialization. The original closed idle kernel translation unit is retired from this candidate's compile matrix; its source and state ABI remain unchanged. Only the Kmod shim is transformed to select the new two-class backend and experimental bundle identifier.

The 144-byte request binds the real registry generation, generated 80-byte source/policy identity, immutable native code contract, exact target build, actual userspace `kern.stack_size` observation and explicit retained-experiment acknowledgement. The runtime independently checks the actual native profile and its retained owner/epoch/cancellation conditions. No request field is a global/RM/PM readiness Boolean.

Snapshot version3 preserves the shared 104-byte preparation observation, including its 56-byte PM record, and appends a 144-byte runtime record and 64-byte IRQ source record. The total snapshot is776 bytes. The cached Owner observation preserves the first failed stage and status through private cleanup and subsequent stop calls. The client reports stage labels, observation masks and validity separately; unobserved host facts, device predicates and PM predicates are `null`. Zeroed or malformed observations cannot imply successful preparation. Snapshot size and version must match exactly; request, generated identity and native-profile formats are unchanged.

The runtime reports its last entered stage and first failed stage separately from the final FAILED marker. Per-call attempted and returned masks distinguish a genuine `NV_ERR_NOT_READY` return from a never-filled status slot. A completed original global call is separate from an attempted or returned original adapter call. Unknown or raced runtime snapshots expose `null` facts and call statuses. IRQ probe counts and hardware MSI capabilities are separate from an OS-selected MSI source; source0 is a valid known index. Duplicate or incomplete MSI observations cannot appear as a valid selection. These records grant no execution or release authority.

Device predicates describe the preparation checks: a false D0 predicate means D0 was not confirmed. An earlier PCI or BAR failure can skip later hardware reads, so these fields do not identify a physical D3 state.

The real control retain, Owner facade, provider reference and module remain pinned after a valid request, including a preparation failure. A stop still attempts the actual Owner protocol. Buffers and IOVAs visible to original code or lacking a proven stop remain retained; checked pre-original cleanup is permitted. Diagnostic snapshots never authorize reclamation. A requester closing its connection requests a real stop; closing another read-only client's connection does not cancel the request. Up to16 privileged clients allow a separate process to inspect or request cancellation during a synchronous first call; the initialization one-shot remains independent of connection count.

Actual CPU controls compile the C state implementation, extract the real backend lifecycle bodies into explicit fixture types, and include the unchanged userspace client against fake IOKit/CF/sysctl APIs. They cover owner publication under the actual shared lock, stop arriving during prepare, cancellation publishers joined before stop, read-only close behavior, identity/capacity/replay refusals and truthful RPC/stop reporting. B6 adds post-bind IRQ failure, successful MSI source0/source1, inflight versus returned status85, malformed/old snapshots, raced observations and unknown route controls. Backend fixtures use the actual profile-expanded runtime declaration; the runtime producer itself remains an explicit fake endpoint in those lifecycle controls. Positive controls pass in plain and fatal sanitizer modes; mutants removing those guards fail. Six complete frontend/reference translation units also compile to Mach-O against the actual pinned kernel SDK under the same15.0 availability profile as the native job. These are source/ABI controls, not a native image, target load, initialization or acceleration result.

`VALIDATION.json` binds the actual sources and raw evidence. `experimental_ctl --snapshot` reads cached wire diagnostics; `--stop` requests actual stop from another root connection; `--run-once --ack-retained-first-initialization` performs the one request and then a real stop on the same connection. The eventual signed package compiles this exact client with the independently verified image's source, policy and native-code digests.
