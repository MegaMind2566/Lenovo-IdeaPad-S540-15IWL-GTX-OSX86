# Exact native retained-experiment package

`package_verified_plan` accepts the current replay callback and an independently supplied native image report SHA256. It requires actual Intel Apple execution before any package output. It rechecks the entire current native compile matrix, source/command/dependency captures, compiler/SDK/helper bindings, fresh preliminary/final machine-code graph inputs, immutable native budget, exact SDK references,25 original roots, module-runtime bytes, three metaclasses, final private closure and public KPI export provenance.

The packager builds the userspace client from the actual composed source with image-bound source/policy/native-code digests. It signs the real kext and client, then independently checks that signing changed only allowed signature/LINKEDIT metadata and preserved code, data, import/export/loader pointers, firmware, profile and Kmod semantics. It never loads code or changes security settings.

The B9 output container holds `S540ExperimentalInitRetained/`, `S540ExperimentalInitRetained-B9.zip`, an outer copy of the attestation and package digests. The payload has the signed bundle/client, explicit target-test script, full file manifest, report evidence, firmware notice and corresponding sources. The source archive includes every materialized original/project file, recipe inputs and pinned SDK, preserving actual executable modes. Real `unzip` roundtrip controls restore the inventoried original/project bytes and modes, including executable original files and pinned SDK files; removing the original legal notice is refused.

B5 classifies the optional I/O BAR in slot 5 separately from memory BARs and does not map it as MMIO. The three verified MMIO BAR requirements and existing mapping checks remain in force. It accepts normal PCIe endpoints (type 0) and legacy PCIe endpoints (type 1), including the authentic `IOPCIExpressCapabilities=0x12` value. Other device/port types remain refused. This classification uses the already-read flags and adds no PCI access. The physical B5 test passed all seven PCI predicates and preparation, completed global RM initialization, and returned status 86 after transaction binding before adapter initialization. The exact IRQ refusal was not exposed by its snapshot.

The target script verifies the independent attestation and every payload file before loading a fresh root:wheel copy. It distinguishes loader admission, control readiness, request/RPC results and actual stop diagnostics. It issues no unload; a load accepted or left uncertain requires reboot under the test policy. Original-visible or uncertain resources remain retained, with checked pre-original cleanup permitted. Successful packaging does not establish target loading, RM/GSP initialization or acceleration; the actual Lenovo report remains necessary.

B6 selects the unique message-signaled interrupt from the actual Apple-published source inventory instead of assuming source zero. The same retained source index is used for registration, enabling, disabling and unregistering; callback dispatch verifies that source identity. The single-vector MSI and no-MSI-X profile remains required. Snapshot v3 reports the attempted/returned runtime stages and observed IRQ route; unavailable observations remain explicitly unavailable. These diagnostics grant no hardware, PM, reclamation or unload authority.

The physical B6 Lenovo test selected MSI source 1 from two published sources, completed IRQ installation and entered and returned from the original adapter wrapper. Adapter initialization failed with status 86 (`NV_ERR_NOT_SUPPORTED`); the kernel log places a failure in the GSP shared-queue allocation. The exact composed queue source requests a 2 MiB GPU descriptor page size and unprotected host memory, while the Darwin allocation bridge accepts 4 KiB pages and rejects `unencrypted=1`. Both contract mismatches must be addressed. The report does not establish successful GSP/GPU initialization or acceleration. Its retained stop did not authorize physical release; software IRQ drain alone is insufficient.

B7 makes two scoped memory changes. The GSP shared queue requests the backend's real 4 KiB base pages before its first allocation, preserving the unprotected request, original error and cleanup paths. The host-memory bridge admits that request only after a private native CPUID check establishes the selected GenuineIntel family 6/model `0x8e` profile, basic leaf 7 availability, no advertised hypervisor and no TME capability. Unknown CPUs, short enumeration, advertised hypervisors and TME-capable hosts remain refused. Ordinary owned, prepared, physically verified and zeroed IOBuffer pages retain the existing allocation, DMA mapping and lifetime rules; no request flag is cleared and no encryption MSR or security setting is changed. SGX capability does not make these ordinary pages enclave EPC memory. This narrow eligibility check trusts the native host and cannot cryptographically exclude a hypervisor that masks CPUID; it is not a general memory-encryption attestation.

B7 adds bounded scalar diagnostics for allocation geometry, request flags, CPUID observations, failure stage and status: the first unprotected request and at most 16 further allocation failures are logged in ordinary context. A nonzero original-wrapper result also logs the actual first-transaction status/site/phase and cached service counters; an unavailable snapshot reports its status without invented values. No object pointers or firmware contents are logged.

The physical B7 Lenovo test admitted the exact delivered image, reached control readiness, completed preparation, global RM initialization, context binding and IRQ setup, then entered and returned from the original adapter wrapper with status 86. Neither adapter initialization nor firmware loading succeeded. Its new diagnostic reports `firstSite=2`, the generic `SITE_ROOT`; `(0x22:0x56:954)` records the outer `gpumgrAttachGpu` failure rather than identifying a constructor. The old queue-allocation error and the new allocation log are both absent, so the report does not establish that the 4 KiB or unprotected-memory allocation path succeeded.

The B7 service counters are cached in the first-transaction record. Their normal refresh points can be skipped after a sticky error, so zero values may be unsampled. Even a fresh `memoryUnavailableEver` measures the unsupported-memory service, while supported allocation attempts and failures use separate `AbiStatistics`. Source review also found that retained constructor cleanup returns a nonzero status before NVIDIA's optional-engine `NV_ERR_NOT_SUPPORTED` conversion; a missing optional engine is one possible explanation. An upfront GSP-client-mode refusal is another source-level lead. The B7 report proves neither branch, and returning success while retaining a failed published child would not restore valid ownership semantics.

B8 adds diagnostic observers for the actual attach stage, constructor class and instance, construction stage, raw status and available missing-engine observations. These bounded scalar witnesses are captured during the real call and emitted only after the original wrapper has returned. The outer diagnostic labels cached counters separately from fresh service-counter reads and a separate atomic allocation observer. That observer captures actual allocation entry, attempt and failure sites; its counters are sampled independently over the module lifetime, and its immutable first-failure tuple is available only after complete publication. Read status and first-failure availability are explicit. The diagnostic does not read mutable `AbiStatistics`, live Session state or allocation tables. This avoids adding a formatting buffer deep in the constructor stack. Existing admission, error propagation, retention and cleanup rules remain in force; no failed constructor is converted to success and the userspace snapshot wire protocol is unchanged. Native validation, packaging and Lenovo execution remain separate milestones.


The physical B8 Lenovo report matches the delivered B8 attestation. It passed kernel loading, control readiness, preparation, global RM initialization, context binding and IRQ setup; the original adapter returned status 86. The first constructor witness identifies attach stage 5 (`gpuPostConstruct`), class `0xce6818` (`KernelNvlink`), instance 0 and constructor stage 7 (`engstateConstructEngine`). The observed `gspClient=1` describes the GPU mode, not the failing class. The first tuple was captured before the missing-engine property was sampled, so it does not establish that property. The fresh allocation observer recorded six module-lifetime attempts, no recorded failures or entry rejections, and a largest request of 129 pages. These independently sampled counters do not establish every request's flags, later allocation geometry or callback quiescence. Fresh `hostUnavailable=2` is an aggregate without call-site identity. Adapter initialization and the successful firmware milestone remain unobserved, and retained stop grants no physical release authority.

B9 handles the optional NVLink engine before allocation and child publication. Its narrow absence path requires the exact `KernelNvlink` class and instance, an empty child slot, the real NVLink core's uninitialized state, the checked `NvLinkDisable=1` registry setting and actual first-transaction authority. An initialized core and other engine classes keep their original construction paths. This preserves the normal NULL-child representation of an absent optional engine without deleting a published object or converting a failed retained child to success. It does not initialize the NVLink backend or assert NVLink hardware support.

B9 also adds a private atomic observer for unavailable host-service IDs and selected host call sites. The original aggregate count and refusal behavior remain intact. Bounded scalar records are emitted only after the original adapter wrapper returns; counters cover the module lifetime and are sampled independently, while the first observation is read only after full publication. External site 0 remains explicitly ambiguous where no precise call site was observed. No HostSnapshot or userspace wire layout changes, reset API, pointer logging or deep-callback logging are introduced. The retention, stack assumptions, PM/DMA-stop and acceleration limits remain unchanged. B9 native validation, verified packaging and its next physical Lenovo test must each provide their own evidence; this document does not anticipate their outcome or publish a B9 attestation hash.
