# Darwin platform facts and endpoint ACPI

This component collects the platform record required by the original global RM. It supplies the real Darwin `nv_acpi_rom_method` boundary for the exact retained PCI endpoint. It does not initialize a GPU or stand in for adapter/GSP initialization.

`Context::initialize(provider)` retains the selected endpoint and resolves only its published `acpi-path` alias, following Apple's `IOPCICopyACPIDevice` implementation. Facts collection can precede global-host allocation. After the adapter context exists, `bindState(state)` binds its exact identity once; ROM access is unavailable before binding. The resolved entry must be an active `IOACPIPlatformDevice`. No PCI bridge, arbitrary service parent, guessed ACPI pathname, or unrelated ACPI device is substituted. A missing companion or `_ROM` method is recorded explicitly and the bound ROM call returns `NV_ERR_NOT_SUPPORTED`; original RM decides whether its fallback applies.

`collect(&facts)` publishes a partial record with a known-bit mask and returns `NV_ERR_NOT_READY` unless every required fact is established. Unknown facts are not converted into negative answers.

| Fact | Actual source |
| --- | --- |
| Registered CPU count | Exported XNU `unsigned int real_ncpus`, populated from registered processors |
| CPU frequency | Exported XNU `gPEClockFrequencyInfo.cpu_frequency_hz`; a zero value leaves the CPU fact unknown |
| EFI | Kernel-recognized `gPEEFISystemTable` pointer |
| Notebook chassis | SMBIOS Type 3 chassis values 9/10, including the defined lock bit; unknown or malformed records are refused |
| Rechargeable battery | Actual ACPI namespace `_BIX`/`_BIF` package technology field, matching the original NVIDIA predicate |
| NVIDIA vGPU hypervisor | Explicit non-`NV_VGX_HYPER` build profile; this is separate from generic CPU hypervisor detection |
| NvSwitch presence | Current published PCI inventory: NVIDIA vendor and PCI bridge-other class, matching the original predicate |
| S0ix | Explicitly disabled operational policy for the initial adapter profile; FADT hardware capability is collected separately |
| OS version and date | Running kernel globals from `libkern/version.h`, not the SDK's build-time version macros |

AppleSMBIOS publishes its table either as data or through its original serializer. The serializer path requires a checksum-valid bounded SMBIOS entry point first. The decoder reads only the chassis byte and never publishes table contents, identifiers, serial numbers, addresses, or registry paths. Registry enumeration has a finite node budget and an invalidated/incomplete enumeration leaves the relevant fact unknown.

`collectSegment` walks the exact companion's ACPI ancestors until it proves a PCI root bridge through `_HID` (`PNP0A03`/`PNP0A08`, string or compressed EISA ID). It reads that bridge's `_SEG`. ACPI's segment-zero default applies only after that identity proof and an explicit missing-object result; unrelated evaluation failures remain unavailable.

`collectDeviceFacts` records the selected provider's actual configuration header, BDF, segment, three assigned BAR descriptors and D0 state, without sizing writes or BAR mappings. It requires the exact pinned TU117/subsystem/revision identity and checks descriptor lengths against assigned BAR addresses. A null PCI handle is permitted during construction; the real transport token must be installed before adapter preparation. Console proof enumerates every published framebuffer within 4,096 nodes and walks each active console's retained service ancestors within 64 entries. It requires at least one positive Intel display owner and excludes the exact bound NVIDIA PCI endpoint from every console. Unknown owners, invalidated/incomplete iteration, exhausted bounds or missing Intel ownership leave the result not ready. `IOFramebuffer::isConsoleDevice()` is queried on each real object; no source contract guarantees that finding one Intel console proves global uniqueness. The immutable `intelConsoleVerified` and `nvidiaConsoleExcluded` facts are both required by context construction and the non-console screen callback. This query is a bounded startup snapshot, not a power reference. `noCoherentGpuMemoryProfile` refers to NVIDIA's separate coherent GPU-memory/NUMA feature: the original Linux discovery immediately returns on non-AArch64. It does not describe or disable coherent x86 host-memory DMA.

The `_ROM` bridge accepts only the exact bound `nv_state_t` identity in ordinary thread context. Each request supplies offset and length as two ACPI integers. Requests are limited to 64 KiB within a 16 MiB ROM window. The returned object must be bounded data covering the request. Failed calls preserve the output buffer. Inputs, parameter objects, result objects, and companion/provider references retain distinct ownership.

The caller keeps this context alive through original adapter shutdown and callback quiescence. `unbindState(state)` removes the exact ROM identity while retaining the provider and facts for transport cleanup. The bootstrap owner copies OS fact strings into its own storage before host initialization, so its host record survives later platform detach. Every context operation is externally serialized by the persistent RM owner. Facts collection itself creates no worker, interrupt handler, user client, kernel file reader or power transition.

The native check exercises the production byte decoders, malformed tables, contradictory chassis records, ROM-window bounds and the shared complete-console ownership policy. Its 62 checks include unknown owners, contradictory target ownership, absent Intel ownership, invalidated enumeration and counter overflow; provider and registry objects are not fabricated. Native builds deliberately refuse Darwin collection rather than fabricate platform facts. Darwin source compilation against the pinned SDK establishes type compatibility; actual runtime collection and GSP execution remain separate evidence.

`S540NvidiaGspPower::Lease` owns a separate, private `IOService` child below the exact PCI endpoint in the power plane. It registers a real two-state PM driver and requests `kIOPMPowerOn` through that child's own desire. It does not overwrite the nub's existing policy. Acquisition requires the actual power connection and the completed on transition; neither a retained provider, a sampled PMCSR D0 bit nor an accepted PM request is sufficient.

A subsequent down request revokes the session permanently and posts shutdown to the same persistent thread that created the RM context. Queue acceptance does not acknowledge the power change. The worker first stops original RM, interrupt producers, DMA, MMIO and host owners. It then submits `acknowledgeSetPowerState`. A separate guarded count requires every external revocation hook to return before the owner can close; Apple's `PMstop` waits for driver callouts for a bounded interval and cannot prove that lifetime itself. Failed cleanup, acknowledgement or hook completion retains the power service and worker for retry. Apple's emergency-sleep paths and PM timeout escalation remain outside a driver's power guarantee; the service never reports a failed drain as successful acknowledgement.

The completed child lease admits resource preparation only. `PowerLifetime` remains blocked because original FWSEC/Booter waits can allow at least 60 seconds during initialization, while the PM callback declares 30 seconds for the queued shutdown to finish. Normal sleep can exhaust that deadline before the worker returns from original code. On the pinned macOS implementation, ordinary drivers' `kIOPMPreventIdleSleep` state-table flags do not prevent system idle sleep. The [source-bound deadline audit](POWER-DEADLINE-AUDIT.md) distinguishes those facts from emergency power loss and specifies the original-entry cancellation and bounded teardown evidence still required.

`POWER-PROVENANCE.json` pins the Apple implementation and SDK declarations. The independent SDK reference covers the PM and deadline APIs. The native power protocol check uses explicit PM events and verifies delayed completion, monotonic revocation and acknowledgement refusal; it does not claim an acquired Darwin power domain. The combined bootstrap fixture separately exercises real persistent-worker dispatch and teardown before acknowledgement. Its concurrent hook test blocks the external callback after enqueue, verifies that acknowledgement cannot release its owner, and retries stop only after actual callback return.
